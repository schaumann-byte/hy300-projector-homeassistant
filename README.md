# HY300 Projector for Home Assistant

> *Generated by [aurora@aurora-smart-home (ha-integration-dev skill)](https://github.com/tonylofgren/aurora-smart-home)*

Local control of the cheap **HY300 Pro+ / Magcubic** Android projectors from Home Assistant, with no cloud. The integration tracks whether the projector is really on, and handles power, volume, remote keys, focus/keystone/zoom and opening any app (SmartTube, Stremio, Crunchyroll…). It turns the projector on with **any IR blaster**. The repo also includes a tiny Android helper app that keeps **wireless ADB** alive across reboots and puts your **preferred launcher** in front at boot.

> 🇧🇷 **Resumo em português** no fim da página.

## Tested hardware

| | |
|---|---|
| Projector | HY300 Pro+ (Magcubic), "H726 Standard", Android 14, `armeabi-v7a` |
| Firmware | Lumina Go **v3.0.0** (web remote on port 8899) |
| IR blaster | Tuya IR/RF blaster (ZC-XZ IR-RF) via [`tuya_local`](https://github.com/make-all/tuya-local). Any `remote` entity that can learn codes (e.g. Broadlink) should work. |
| Home Assistant | 2026.8 (needs ≥ 2025.3) |

Other HY300 variants with the Lumina Go web remote probably work too. Check `http://<projector-ip>:8899/` in a browser.

## How it works

```
                 ┌──────────── Home Assistant ────────────┐
                 │  hy300_projetor integration            │
   power-on ◄────┤  • IR blaster: remote.send_command     │
   (IR)          │  • Lumina Go HTTP API :8899 (keys,     │
                 │    volume, power-off, on/off state)    │
                 │  • ADB (optional) via adb-server :5037 │
                 └──────────────┬─────────────────────────┘
                                │
          ┌─────────────────────┴──────────┐
          │ adb-server container (holds the │──TLS──► projector adbd :5555
          │ paired key)                     │
          └─────────────────────────────────┘
```

- **Lumina Go API (no auth, LAN only).**
  - `GET /api/v1/device` returns the model, firmware and the list of 130 commands.
  - `POST /api/v1/command {"command":"VOL_UP"}` sends a command.
  - The API only answers while the projector is on, which gives a reliable on/off state.
- **Power-on over IR.** With the projector off, its Wi-Fi is down, so there's nothing to talk to on the network.
  - After sending the IR code, the integration polls the API for 75 s and **resends the IR once** if the projector didn't come up.
  - If it still fails, it raises a notification and fires the event `hy300_projetor_power_on_failed`.
- **ADB (optional).** Used to open any app by package name and to show which app is on screen.
  - The projector's `adbd` only accepts **TLS connections from a paired key** (Android 11+ wireless debugging), and pure-Python ADB libraries can't do that.
  - So a regular `adb` server runs in a small container next to Home Assistant, and the integration talks the adb smart-socket protocol to it.

## What you get

- `media_player.projetor`:
  - on/off, volume up/down, mute, play/pause/next/previous;
  - **sources**: apps opened through ADB (SmartTube, Stremio, Crunchyroll), plus Home, All apps, HDMI input, Screen mirroring and USB;
  - `app_id` / `source` show the app on screen (with ADB).
- `remote.projetor_controle`: sends any of the API commands from automations. Destructive ones (`FACTORY_RESET`, `CLR_DATA`…) are blocked.
- **18 buttons**: D-pad, OK, back, home, menu, settings, input, focus ±, auto focus, keystone, zoom ±, play/pause, sleep.
- `binary_sensor.projetor_adb`: whether ADB is ready (apps can be opened).
- `sensor.projetor_firmware`.
- Example dashboard view: [`examples/dashboard-projector-view.yaml`](examples/dashboard-projector-view.yaml).

> Entity names are in Portuguese (the author's language). Rename them in the UI if you like. App packages live in `SOURCES` in `const.py`.

## Setup

### 1. Projector: developer options and wireless debugging

The vendor "Developer options" menu only shows *ADB debug* and *USB debug*. The switch that matters, **Wireless debugging**, lives in the **stock Android Settings**, which the vendor UI hides.

1. Install **[Projectivity Launcher](https://play.google.com/store/apps/details?id=com.spocky.projengmenu)** from the Play Store. It gives access to the stock Android settings.
2. In Settings → About, tap **Build number** repeatedly to enable developer options.
3. Stock Settings → System → **Developer options** → turn on **Wireless debugging**. Tap it → **Pair device with pairing code**.
4. From the machine that will run the adb server:
   ```sh
   adb pair <projector-ip>:<pairing-port> <6-digit-code>
   adb connect <projector-ip>:5555
   ```
   Tip: the pairing port changes every time. If you can't read it, scan the projector for a newly opened port.
5. Wireless debugging is **switched off on every reboot** (Android behaviour). Step 4 of the next section fixes that.

Avoid *USB debugging* on this model: it disables USB peripherals.

### 2. ADB server

Run [`examples/docker-compose.adb-server.yml`](examples/docker-compose.adb-server.yml) on the Home Assistant Docker network, and mount the folder holding the key you paired with (`adbkey`, `adbkey.pub`). Home Assistant then reaches it as `adb-server:5037`.

### 3. IR power code

Learn the POWER key of the projector remote with your IR blaster ([`examples/ir-learn-power.yaml`](examples/ir-learn-power.yaml)).

### 4. ADB Boot helper app (keeps wireless ADB on and fixes the launcher)

[`android-adb-boot/`](android-adb-boot/) is a ~12 KB app with no UI, no activity and no INTERNET permission. On every boot it:

- sets `adb_wifi_enabled=1`, and again once the network is up, so ADB comes back without touching the projector;
- sends a `HOME` intent, so your **default launcher** (e.g. Projectivity) comes to the front instead of the vendor one.

**Why the launcher fix is needed:** the vendor launcher `com.htc.magcubicos` is a *direct-boot-aware* system app. The system starts it at boot before any user launcher can run, even when another app holds the HOME role. Changing `persist.sys.homePackage` has no effect.

Install it with a prebuilt APK from [Releases](../../releases) (or build it yourself, see its README), then:

```sh
adb install -r adbboot.apk
adb shell pm grant br.casa.adbboot android.permission.WRITE_SECURE_SETTINGS
adb shell appops set br.casa.adbboot SYSTEM_ALERT_WINDOW allow   # launcher fix
adb shell am broadcast -n br.casa.adbboot/.BootReceiver          # run once so it leaves "stopped" state
```

Then pick Projectivity as the default launcher (Home button → choose → Always).

### 5. Integration

1. Copy `custom_components/hy300_projetor` to your `config/custom_components`, or add this repo to HACS as a custom repository (Integration). Restart Home Assistant.
2. Settings → Devices & services → **Add integration → HY300 Projector** → enter the projector IP. The projector must be on.
3. **Configure** the integration:
   - IR blaster: the `remote` entity, plus the device/command names you learned;
   - IR retry;
   - **Use ADB**, with host `adb-server` and port `5037`.

Reserve the projector's and the IR blaster's IPs in your router's DHCP.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Shows *off* while on | Check that `http://<ip>:8899/` loads. The IP may have changed. |
| Doesn't turn on | Aim the IR blaster at the projector. After 2 attempts you get the "Projetor não ligou" notification. |
| App tiles grey / "ADB not ready" | ADB comes back about 1 min after boot. Check `adb logcat -s AdbBoot` for `adb_wifi_enabled=1 (BOOT_COMPLETED)`. |
| `adb connect` fails with no prompt on screen | The device answers `STLS`, so it needs pairing (section 1). |
| Vendor launcher still shows at boot | Make sure the `SYSTEM_ALERT_WINDOW` appop is allowed and your launcher is the default. |

## Notes / limitations

- There is **no standby** in this firmware. `SLEEP` and `KEYCODE_SLEEP` do nothing, and `POWER` is a full shutdown (~12 s).
- The API has no state endpoint (volume, current app). The current app comes from ADB (`dumpsys activity`).
- The `SET_*_PERCENT` commands take a value in an unknown format and are not exposed.
- The `KEYCODE`s of the vendor remote are not needed. Everything goes through the Lumina Go API.

## 🇧🇷 Resumo em português

Integração local para projetores **HY300 Pro+ / Magcubic** (Android 14, firmware Lumina Go):

- controla pela API da porta 8899 (teclas, volume, foco, keystone, desligar e estado real);
- **liga por IR** com qualquer emissor que aprenda códigos. Confirma se ligou, reenvia uma vez e avisa se falhar;
- com ADB (opcional), **abre qualquer app** (SmartTube, Stremio, Crunchyroll) e mostra o app na tela.

O app **ADB Boot** religa a depuração sem fio a cada boot, porque o Android 14 desliga, e coloca o **launcher padrão (ex.: Projectivity)** na frente do launcher de fábrica.

Passo a passo:
1. Instale o Projectivity para chegar nas configurações originais do Android e ativar a **Depuração sem fio**.
2. Pareie com `adb pair`.
3. Suba o container `adb-server`.
4. Aprenda a tecla POWER no emissor IR.
5. Instale o ADB Boot, conceda as permissões e adicione a integração no HA.
